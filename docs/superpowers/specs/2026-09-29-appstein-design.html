Why

Models are smart enough. What they lack is context and a check.

Without accurate, current, project-specific context and a reliable check on their output, agents fall into four traps.

How it works

Two halves, one loop.

Guided properly, agents produce fewer bugs and spend fewer tokens, because they no longer rediscover where everything is.

1Before the agent writes

A knowledge layer that never goes stale.

Generated from the installed SDK and the analyzed code; the small hand-written part is checked. Served through files and an MCP server.

  • Version delta: “use X, not Y” for this SDK
  • Project map: features, routes, layers, native config
  • The valid native toolchain for this Flutter
  • Decisions and memory that outlive a session
2After the agent writes

A verifier that blocks “done” until the work is correct.

Deterministic checks, not prompts. Findings go straight back to the agent.

  • Analyzer, deprecated APIs and custom lint rules
  • Android and iOS native-config audit
  • Package gate against invented or unsafe packages
  • Real debug builds

One agent session, start to finish

Hooks call the appstein binary directly, with no shell scripts, so they work on Windows too.

Session starts

Refresh knowledge

appstein sync

Creates or refreshes .appstein/, including INDEX.md.

After every change

Fast check

sync --detectverify --fast

Only reports. Never rewrites a file mid-session. Target under 5 s.

Needs context

Ask, don’t search

overview · where_ischeck_api · toolchain

MCP answers from fresh knowledge in under a second.

Agent says “done”

Full check

dart fix --apply + formatappstein docsverify --full

Errors block the finish. After the same errors block 3 times in a row, it stops blocking and shows them to you.

Details

Bash changes are caught too. --detect compares content hashes with state.json, so flutter pub add is checked like an edit. When nothing the knowledge reads changed, it stops there; otherwise it rebuilds with the analyzer cache in .dart_tool/appstein/.

Dependencies changed? The same hook runs the package gate and re-runs dart run skills@ get for package skills.

Why fixes wait for Stop: rewriting a file the agent just read makes its next edit fail.

No SessionStart hook (Codex): AGENTS.md says to call overview first, which syncs if knowledge is missing or stale.

Knowledge

Four layers. One small page always in view.

Only INDEX.md is always loaded, at most 1,500 tokens (measured as 4,500 bytes). Everything else is fetched on demand. When the page would run long, the least important parts are cut first, each pointing to the MCP tool that has the rest.

Details

Delta baseline: the curated notes reach back to Flutter 3.16 by default, so WillPopScope → PopScope and textScaleFactor → TextScaler are covered. Deprecations and migrations are listed whatever their age, since every one of them fails verify.

Filtered and ranked: deprecations and migrations (removed APIs included) from the SDK and the packages, only where the project’s imports expose them; every note since the baseline, by priority. The project’s language version gates new syntax.

Staleness is detectable: every generated file carries a hash of its inputs, and verify fails with knowledge.stale on a mismatch.

Never guessed: routes or native values that can’t be resolved statically are marked unresolved or unknown.

Details

Nothing written just for the docs. Concept text ships inside each pack; project text comes from decision reasons and /// doc comments, required by document_public_classes.

Quiet in git: no timestamps, so unchanged code gives unchanged docs. A conflict is fixed by re-running appstein docs.

Kept honest: docs.stale warns when docs fall behind or a generated page was hand-edited. Teams can raise it to an error.

Team notes are safe: any file in docs/app/ without the Appstein marker is never touched and is listed in the README.

Appstein’s own repo too: graphify serves agents; a developer guide in docs/guide/ and dart doc API docs serve humans. CI keeps the guide current: every source file maps to a guide page, and generated facts can’t drift.

Verifier

Check, don’t hope.

Every rule an agent is told is also enforced by a deterministic check wherever possible. Errors block; warnings inform.

Code

  • dart analyze on changed files and dependents; fails on errors and deprecated use
  • dart fix --dry-run lists pending migrations
  • Format check, applied later at Stop

Lints

  • appstein_lints rules, run inside the analyzer
  • Layer rules from the stack pack

Packages

  • Package gate, if dependencies changed
  • Package skills refreshed

Knowledge

  • Incremental map refresh
  • Staleness check
  • Under 5 s with warm analysis (1d)

Code

  • fix + format first, then every fast check on the whole project
  • flutter test with accessibility guideline tests
  • Every feature folder has a test
  • Decisions still match the code
  • Human docs up to date (warning)

Android

  • Toolchain inside Flutter’s matrix
  • AGP 9 built-in Kotlin rule
  • flutter.* SDK variables; compile/target SDK ≥ 36; minSdk covers every plugin
  • 16 KB page size: NDK r28+, zipalign -c -P 16
  • No signing secrets in git · real debug build

iOS

  • Deployment target ≥ SDK minimum (15 on 3.47), consistent everywhere
  • SwiftPM on; plugins without it flagged (CocoaPods read-only 2026-12-02)
  • UIScene manifest
  • PrivacyInfo + usage descriptions
  • Real build on macOS only

Release-ready (static)

  • App / bundle ID not com.example
  • App name and icon not the template default

  • Signing config present or marked TODO

Details

Packs: official_mvvm (stack), android and ios (platform) in M1. They start as folders and become packages when community packs arrive (M3+).

Runs everywhere: Windows, macOS and Linux; paths with spaces and non-ASCII characters.

Offline and private: everything but package existence and advisory checks works offline. No telemetry.

Deterministic: the same inputs give byte-identical knowledge and human docs. An operating-system lock stops two hooks corrupting it, and a crashed writer never leaves it stuck.

appstein upgrade

Keeps a project current after a Flutter or Appstein upgrade.

  • Versioned migrations: one folder per Flutter minor version
  • Flutter’s own migrators (dart fix) run first
  • --dry-run previews the diff; git is the undo, so a dirty tree is refused
  • Example: 3.47/ moves to material_ui, only when every dependency is compatible
