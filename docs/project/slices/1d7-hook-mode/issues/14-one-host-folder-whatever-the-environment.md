# One host folder whatever the environment

**What to build:** on macOS and Windows the analysis host's folder still comes from environment variables, so two clients of one user on one machine can choose different folders and start a host and an analysis server each. macOS takes `$TMPDIR`; an SSH session usually has none, and its client then uses `appstein-<uid>` in the shared `/tmp`, where another user can make that folder first (the case ticket 12 solved on Linux). Windows takes `%LOCALAPPDATA%`; a process started without it falls to another folder. Ticket 12 chose Linux's folder from what every process of the user shares; this ticket does the same on macOS and Windows (the owner, 2026-10-22).

**Blocked by:** 12.

Status: claimed

- [x] macOS: the folder is `appstein` in the user's own temporary folder as the system names it (`DARWIN_USER_TEMP_DIR`, the name `getconf` uses), not `$TMPDIR`, so a client in an SSH session or with any `TMPDIR` finds the same host, and the shared `/tmp` is never used while the system names that folder. When the system can't name it, the user's `Library/Caches/appstein/hosts/<machine>` under the home from the user database, with ticket 12's checks; then the project's `.dart_tool` place; then, last, `appstein-<uid>` in `/tmp` with ticket 12's handling (the owner, 2026-10-22).
- [x] Windows: the folder is `appstein` in the Local AppData known folder of the user as the system names it for the process's own account, not `%LOCALAPPDATA%` (nor `%USERPROFILE%`, which the system follows unless it is given the account). Then the project's `.dart_tool` place; then, last, `appstein-<the user's SID>` in Windows' shared temporary folder (`C:\Windows\Temp`), which the host makes private to the user; one another user made first is refused, and the client is answered by a server of its own with a notice (the owner, 2026-10-22).
- [x] A machine's folder name keeps its machine ID on macOS and Windows too (the system's host UUID on macOS, the machine GUID on Windows), so a machine that is renamed keeps its folder and never starts a second host (the owner, 2026-10-22).
- [x] The last place before the shared temporary folder, on every system: `appstein/hosts/<machine folder name>` in the project's own `.dart_tool` (ignored by git in Flutter projects; the folder per machine keeps two machines that see one project folder apart, the owner, 2026-10-22), used only when every folder from the project root down to it is the user's own and no other user can write to it (the owner, 2026-10-22). So a user with no folder of their own outside the project (Linux with no `/run/user/<uid>`, no usable home, and `/tmp/appstein-<uid>` taken by another user) still gets a host, and their hooks answer within 5 s instead of starting a cold server each time. The slice spec's "outside the project" becomes "outside the project, or in its `.dart_tool` as a last resort".
- [x] Every client, the host and the measurement tool find the same folder; `APPSTEIN_ANALYSIS_HOST_FOLDER` still moves it; a host follows its folder as in ticket 12; what it costs a hook run is measured (no process start on Windows).
- [x] Tests: the choice with the system's answers given by the test, on every system; that `TMPDIR` and `LOCALAPPDATA` change nothing; on macOS and Windows, the real folder.
- [x] The guide, the slice spec and ticket 02 state the rule.

## Comments

**2026-10-22, built and reviewed; proven on Windows, CI to prove macOS and Linux.** Designed first by a helper (Opus high) that wrote a build brief and probed the owner's Windows; the owner answered its questions (macOS's last place `/tmp`, Windows' last place `C:\Windows\Temp`, `.dart_tool/appstein/hosts/<machine>`, and the machine ID added to this ticket). Built test first by a helper (Opus medium) in its own worktree; reviewed on two axes (standards: Sonnet high; spec and security: Opus high); two fix rounds by the same helper, the first checked by a helper (Opus high), the second by Claude. The status stays `claimed` until a CI run proves the macOS and Linux parts.

- **How it works.** The host's folder is chosen on every system from facts the user's processes share, never from `TMPDIR`, `LOCALAPPDATA` or `USERPROFILE`, through a new seam for the system's answers (`SystemCalls`, `dart:ffi`, no new package).
  - **Windows:** `appstein` in the Local AppData known folder for the process's own token (`SHGetKnownFolderPath`; without the token the system follows the process's `USERPROFILE`, found by the design probe), else the project's `.dart_tool` place when the Windows access look passes, else `appstein-<SID>` in `C:\Windows\Temp`, made private by the host and refused when another user made it.
  - **macOS:** `appstein` in `confstr(_CS_DARWIN_USER_TEMP_DIR)`, used only when it is the sibling `T` of the user folder (otherwise the system has fallen back to `$TMPDIR`), else `Library/Caches/appstein/hosts/<machine>` in the `getpwuid_r` home with ticket 12's checks, else `.dart_tool`, else `/tmp/appstein-<uid>`.
  - **Linux:** ticket 12's order with the `.dart_tool` place before `/tmp`, looked at in the same single `stat`.
  - **Machine ID:** `gethostuuid` on macOS (a 1 s wait, since 0 waits forever), the `MachineGuid` by `RegGetValueW` on Windows, so a renamed machine keeps its folder; a process that could not read it and the others list each other's folders.
  - **The `.dart_tool` place:** never makes the project root; `.dart_tool` made 755 off Windows; `hosts/.gitignore` of `*`; after `flutter clean` a host writes again only after a 3 s quiet time. Windows access is judged by Win32-OpenSSH's rule, made stricter, with no process started.
  - Hosts follow their folder on every system. Facts are read only when a place needs them.
- **Review rounds fixed:** on Windows a host checks a checked folder's owner and rules after making it private, at its start and whenever it moves (a granted `WRITE_DAC` let another user's folder pass the repair alone); the address goes only into a `.tmp` the host has just created exclusively, so a planted or held file never gets the secret; a host found in another place is used only when it welcomes the client with the secret, and its file is otherwise never deleted or waited on (another machine's host on a shared home is left alone); facts read lazily; no `getent` process on macOS; FFI memory freed on every path; exports narrowed; place kinds an enum; shared kernel32 bindings with `process_identity.dart`.
- **Proof the tests bite:** 17 change-outs in the build, 4 in round 1 and 2 in round 2 each turned their tests red (the builder); Claude took out round 1's owner check after the repair and saw its two tests fail (`+3 -2`), the file restored by hash.
- **Numbers (Windows):** a compiled folder choice took 4.3 to 5.0 ms the first time in a process (the known folder only), 0.0 ms after, with no process started. Engine host tests `+174 ~24` (the builder), `+171 ~24` after round 1 rerun by Claude; CLI `+91`; the measurement's tests `+6`.
- **Not verified yet:** everything macOS (`confstr`, `getpwuid_r`, `gethostuuid`, BSD `stat`), the Linux real-disk tests, and the refusal of a real foreign-owned Windows folder (a seam test only: making a folder owned by another account needs privileges a test can't take).
