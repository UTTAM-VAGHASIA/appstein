# A host folder no other user can take

**What to build:** on Linux with no `XDG_RUNTIME_DIR` (servers, containers, cron), the analysis host's folder is `/tmp/appstein-<uid>`, in the shared temporary folder. Another user can make that folder first. Nothing leaks: the host can't make it the user's own, so it writes nothing there, and the client says why. But no host runs for that user until the folder is gone, so every hook and `verify` call either fails or uses a server of its own. This ticket gives such a user a folder no one else can make, so a host always runs. Found by the CI run of ticket 10 (2026-10-21); the guide was corrected then, and ticket 02's claim that another user "can't even make it first" was wrong.

**Blocked by:** 10.

Status: resolved

- [x] On Linux the host's folder is chosen from what every process of the user shares, not from environment variables (the owner, 2026-10-22, replacing the variables `$XDG_CACHE_HOME` and `$HOME` of 2026-10-21, so that two shells of one user with different variables find one host): `/run/user/<uid>/appstein` when that folder is the user's own; else `.cache/appstein/hosts/<machine>` in the user's home as the system's user database names it; else `/tmp/appstein-<uid>` as before. The machine's folder name keeps machines that share a home over the network apart, also two whose names differ only in letter case or clean up to the same text, and two with the same name (by the machine ID). Windows and macOS are unchanged here (ticket 14).
- [x] Every client, the host and the measurement tool find the same folder. The cache folder is used only when every folder of it that exists, from the home down, is the user's own and no other user can write to it; otherwise the temporary folder is used, and a client whose temporary folder is refused also says why the cache folder was not (the owner, 2026-10-22, after the review found that a home such as `/`, `/nonexistent` or `/tmp`, common in containers and for services, would otherwise let no host run at all). The folders a host makes on the way are made 700, so the choice never changes because of a host. Under root the user's home is never used (its owner is not root).
- [x] The folder-mode rules of the 2026-10-21 fix hold in the new place: it is made 700, its address file 600; a client checks them once there is an address, and refuses a folder others can write to.
- [x] A host follows its folder: when the folder chosen now differs from its own (the machine renamed, the user's last session ended and `/run/user/<uid>` went) or its address file has gone, it writes its address in the folder chosen now, or ends if another host has it. A running host renews its address file's time; a host that starts removes other machines' folders untouched for 7 days (containers renamed at each run, on a home kept on a volume).
- [x] Tests: the folder chosen for each case (with the facts given by the test, on every system), that `HOME`, `XDG_CACHE_HOME` and `XDG_RUNTIME_DIR` change nothing on Linux, and, off Windows, the trust checks on real folders, a host that follows its folder, the sweep, and a folder another process made in `/tmp/appstein-<uid>` no longer stopping a host from running.
- [x] The guide's address-file section, ADR 0002 (if it names the folder), the slice spec and ticket 02 state the new place and how each case is handled, and the false claim is gone everywhere.

## Comments

**2026-10-22, built, reviewed and proven in CI.** Built test first by a helper (Sonnet high) in its own worktree; reviewed on two axes (standards: Sonnet high; spec and security: Opus high); two fix rounds by the same helper, each checked (Opus high); the six findings of the second check fixed by Claude, since the helper rounds were used up.

- **How it works.** `chooseAnalysisHostFolder` picks the folder; on Linux it reads no environment variable but the tests' `APPSTEIN_ANALYSIS_HOST_FOLDER`. The facts come from `MachineFacts` (in `host_environment.dart`), read once per process with no process started where the files tell: the effective user ID from `/proc/self/status` (`id -u` only when it can't), the home from `/etc/passwd` (`getent` in the same single `sh` as `stat` for a user only it knows), the machine ID, the hostname, and the user's private group. The trust look is one `stat -L` for every folder from the home down. The client's address checks tell the owner by one `stat` that does not follow links (`/usr/bin/stat -f %u` on macOS, so Homebrew's GNU `stat` never answers it), no longer by `chmod`, which proved nothing under root. A host makes each missing folder under a name of its own, gives it 700 and renames it into place. Only on Linux is a host told to follow its folder (`--follow-folder`): a 60 s round checks the folder and its file with no process, and every 10 minutes it renews its file's time and looks afresh. At its start it sweeps other machines' folders untouched for 7 days (renamed first, looked at again, renamed back if anything is new), and clears the empty `.making` folders a host that died left, once they are an hour old. A client that finds no host looks in the other places the rule could have given before it starts one. When even `/tmp/appstein-<uid>` is another user's, hooks and the MCP tool are answered by a server of their own with a notice; `appstein mcp` keeps one for the session (`SessionOwnServer`) and stops it when the session ends.
