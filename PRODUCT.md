## Platform

web

## Users

- **Professional Flutter developers.** They use AI coding agents (Claude Code, Codex) and want them to work faster and with fewer errors. They still review the code.
- **Beginners and "vibe coders."** They can't write Flutter code but want a real app they own that builds for the stores.
- **Readers of planning artifacts.** The owner (UTTAM-VAGHASIA) and future contributors.

## Product Purpose

Appstein is a knowledge and verification layer for AI coding agents that build Flutter apps. It works in two steps:

1. **It guides agents before they write code**, with generated, always-fresh knowledge: platform facts for the installed SDK, an exact project map, decisions and memory.
2. **It checks their work afterwards** with deterministic checks: analyzer, custom lint rules, a native Android/iOS config audit, a package gate and real builds. These block "done" until the work is correct.

Success means:

- agents never leave deprecated APIs;
- they find code through the map instead of searching, and use fewer tokens;
- new projects build for Android and iOS on the first try;
- the knowledge never goes stale;
- all of this is measured by a published benchmark.

The long-term goal is a full agentic harness: a single-agent pipeline, then a Flutter desktop app with a team of agents, then a web UI.

## Positioning

Knowledge is exact because it's generated by the Dart analyzer from the installed SDK and the real code, not guessed. Every rule told to agents is also enforced by a deterministic check. Google's official tooling is installed and pinned, not rebuilt; Appstein fills its gaps: version drift, native build config, package vetting, and accessibility/design gates across agents. The closest competitor, Vide, is Claude-only and doesn't cover native config or verification.

## Operating Context

- **Where it runs:** inside the user's own agent sessions, through hooks, an MCP server, skills, and `CLAUDE.md` / `AGENTS.md` pointers. It is a Dart toolkit (the `appstein` CLI) installed via pub.dev or as a binary.
- **Target platforms:** Android and iOS first; every Flutter platform eventually.
- **The development machine:** Windows.

## Capabilities and Constraints

- Appstein never touches agent credentials. It only configures projects in M1, and it will launch official CLIs unmodified in M2.
- It encodes no Play Store or App Store policies, only correct build and config.
- Irreversible steps (app/bundle IDs, signing) need human confirmation.
- Local-first; no telemetry.
- Open source under the Apache License 2.0. A paid Pro tier may come later, in separate, closed code; the core stays Apache-2.0.

## Product Principles

1. **Generate, don't hand-write** knowledge.
2. **Check, don't hope:** every rule has a deterministic check where possible.
3. **Reuse official tooling;** add value only in the gaps.
4. **Never touch credentials;** irreversible steps need a human.
5. **Report honestly,** including benchmark results that disappoint.
